# Master prompt

This is the brief we give Claude at the start of each week. Edit it whenever the team has a new idea or changes a rule, and note the date of the change at the bottom.

## The project

- NAAP is a Flutter app built in Android Studio.
- The code follows the structure of the class project (github.com/Sprajapati123/Ai39D).
- All new code goes in the `NAAP_Blueprint` folder first. The team reviews it and decides whether to use it, edit it or drop it.
- Use algorithms that keep time and memory low, and write the cost next to anything that loops or stores data.
- The Figma design can change as the project goes on. Keep colours, text and sizes in `lib/constants` so a design change touches one file, not every screen.

## How the weeks run

- One sprint per week, taken from the sprint backlog tabs in the Google Sheet (Sprint-1 Backlog, Sprint-2 Backlog and so on).
- The deadline is every Friday, because that is when we have the project consultation.
- Build only the stories in that week's sprint. Don't start next week's work early.
- At the end of each sprint, update `docs/sprint-XX.md` with which story maps to which file and anything left undone.

## Writing style

Write comments, docs and messages the way a student on the team would. Plain sentences, sentence case headings, no em dashes, no filler words, no emoji.
